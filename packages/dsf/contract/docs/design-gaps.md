# Design Gaps

A **Design Gap** exists when implementation evidence shows that safe progress requires canonical product, technical, or Delivery truth to be added, changed, materially clarified, or reconciled. Ordinary engineering difficulty, an implementation defect, or a desire to refactor is not a Design Gap.

A Design Gap attaches to the active work item: an authored Phase, a Milestone Review, or a Milestone Remediation. Stop only affected work and preserve the work-item identity, repository reality, evidence, governing references, authority problem, and decision needed. Independent work may continue when it does not depend on the gap.

Start the human design conversation while the responsible human is available. Do not return terminal `BLOCKED` merely because the next chat turn needs a decision.

After explicit human resolution, update the real project-owned canonical truth, append the required immutable Package Amendment when package truth changed, reconcile affected implementation/run state, and resume. Never mutate pinned `.framework/**` trees or an existing `AM-*` record.
