# Context Accumulation Guide

Complete package orientation once, then load context around the current Phase, Review, Remediation, or repair instead of rereading everything.

For Phase work, read the Phase contract, governing references, supporting Concepts, Repository Orientation, and participating repositories.

For Milestone Review, read the Milestone contract, member Phase results/evidence, exact integrated heads, relevant design authority, and only the deeper code/history needed to judge the whole capability. Fresh specialist context should avoid carrying unnecessary implementation chatter.

As accepted design, implementation history, tests, Git anchors, and evidence grow, agents should use them to settle more routine choices without human help. This progressive autonomy uses existing authority; it never permits agents to invent missing product or architecture decisions.

When accepted context still cannot resolve a genuine authority problem, raise a Design Gap rather than guessing.
